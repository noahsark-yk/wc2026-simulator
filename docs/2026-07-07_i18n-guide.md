## 0. この文書は何か

- 対象: `journey.html`（https://noahsark-wc2026.pages.dev/journey.html ── 旅モード）の多言語まわり全部
- 関連ファイル:
  - `journey.html` ── 翻訳辞書・国名辞書・適用ロジックの全部が入った単一ファイル
  - `tools/i18n_check.js` ── 整合チェッカー（本ガイドの手順の検証に毎回使う）
- 10言語: `ja / en / es / pt / fr / de / it / ko / zh / ar`（ja が基準言語）

## 1. 仕組み

### 1.1 翻訳辞書 TJ

- `journey.html` 内の `const TJ = {`（2026-07-07 時点 L1034。行番号はズレるので `grep -n "const TJ = {" journey.html` で現在地を出す）
- 構造: `TJ = { ja: {キー: "訳文", …}, en: {…}, …, ar: {…} }` ── 10言語 × 259キー（2026-07-07 時点）
- **ja が基準**。キー集合・プレースホルダ集合は ja に全言語が揃う（チェッカーが強制）

### 1.2 TT(key, vars) ── JS からの参照

- 定義: `grep -n "function TT(" journey.html`（2026-07-07 時点 L3724）
- 参照順: `TJ[現在言語][key]` → 無ければ `TJ.ja[key]` → それも無ければ **key 文字列がそのまま画面に出る**
  - だから「キーの消し忘れ・typo」は画面に `js1_ko_r32` のような文字列が出る事故になる
- 変数埋め込み: `TT('js1_no_matches_yet', {v0: 国名})` → 訳文中の `{v0}` が置換される
- **重要仕様**: 置換は `s.replace('{'+k+'}', v)` ── **最初の1個しか置換しない**。
  同じプレースホルダを1つの訳文に2回以上書くと、2個目以降が `{v0}` のまま画面に残る。
  if 同じ値を2箇所に出したい → then `{v0}` `{v1}` と別名にして呼び出し側で同じ変数を渡す

### 1.3 data-i18n 属性 + applyLanguageJ ── HTML 静的テキスト

- HTML 側: `<h1 data-i18n="ts_title">W杯を旅する</h1>` のように書く。
  タグ内の日本語は**初期描画のフォールバック**（起動直後の一瞬と、ja の場合の表示）
- 起動時に `applyLanguageJ()`（2026-07-07 時点 L3726）が全 `[data-i18n]` 要素の
  `textContent` を `TT(キー)` で差し替える。あわせて `<html>` の `lang` と、
  ar のときは `dir="rtl"`（右→左表記）を設定する
- textContent 差し替えなので **data-i18n の中に子タグは書けない**（消える）。
  if タグ入りの文をi18nしたい → then JS 側で `innerHTML = TT(キー)` を組む（TJ の値に HTML を持たせる。既存例: `js2_tourn_progress`）

### 1.4 国名は CN + NAT()

- `const CN = {`（2026-07-07 時点 L3753）: 48カ国コード × 10言語の国名辞書
- `const NATION_NAMES = {`（同 L3738）: 日本語のみの旧辞書。**CN が引けない時のフォールバック**
- 参照は必ず `NAT(コード)`（同 L5146）を通す: `CN[コード][現在言語]` → `NATION_NAMES[コード]` → コード文字列
- if 国名を直書きしたくなった → then 書かずに `NAT('JPN')` を使う（直書きはチェッカー [5/5] の WARN 対象）

### 1.5 言語切替は ?lang= リロード方式

- ヘッダの言語セレクタ（`#langSelectJ`）の change ハンドラ（2026-07-07 時点 L4333）が
  1. `localStorage.userLang` に保存
  2. URL に `?lang=<言語>` を付けて `location.href` で**ページごとリロード**
- **なぜ差し替えでなくリロードか**: 起動時に `const` へ焼き込まれる文字列
  （辞書値から組み立て済みの UI 文字列・データ構造）が大量にあり、
  `applyLanguageJ()` の差し替えだけでは古い言語の焼き込み値が残るため。
  リロードなら全 const が新言語で作り直され、確実に追従する
- 起動時の言語決定 `detectInitialLang()`（同 L3716）の優先順:
  `?lang=` パラメータ → `localStorage.userLang` → ブラウザ言語 → `ja`
- 表示確認に使う URL 例: `https://noahsark-wc2026.pages.dev/journey.html?lang=ar`
  （ローカルの file:// 直開きは teams.json の CORS で崩れる。ローカル確認は puppeteer を
  `--allow-file-access-from-files --disable-web-security` 付きで起動して行う）

### 1.6 整合チェッカー tools/i18n_check.js

- 実行: `node tools/i18n_check.js`（root から。puppeteer 不要・依存ゼロ・数秒で終わる）
- 検査5項目:
  | # | 検査 | 崩れると |
  |---|------|----------|
  | 1/5 | キーパリティ（各言語 = ja と同じキー集合） | FAIL → exit 1 |
  | 2/5 | プレースホルダ集合が ja と一致（重複は WARN） | FAIL → exit 1 |
  | 3/5 | 空文字値・文字列以外の型 | FAIL → exit 1 |
  | 4/5 | CN が48コード × 10言語で完全 | FAIL → exit 1 |
  | 5/5 | 辞書外の生日本語行（未TT化候補） | WARN のみ → exit 0 |
- 期待出力（正常時の末尾）: `総合判定: GREEN ── FAIL 0 件 / WARN 84 件 → exit 0`
- **WARN 基準値 = 84 行（2026-07-07 時点）**。内訳は意図的・既知の日本語:
  - `<title>` / `<h1>` / 凡例・パネル見出し等の HTML 直書き（将来の TT 化候補）
  - `VENUES` の会場名・都市名データ（日本語データとして保持）
  - `COMMENTARY` / `GOAL_LINES` / `ANALYST_LINES` / `punditLine` の実況テキスト群
    （L5177 のコメントどおり「実況エンジン Phase 1 = 日本語実況」の意図的仕様）
- if WARN が 84 より増えた → then 増えた行番号を見て、UI に出る文言なら §2 の手順で TT 化する。データ・コメントなら放置してよい（基準値をこの文書で 84→新値に更新する）

## 2. 手順A: UIテキストを「追加する時」

1. キー名を決める。ルールは「TJ 内で未使用」の一点（TT はキー名の形式に依存しない）。
   既存の慣習: HTML 静的 → `html_`、JS 動的 → `js1_`〜`js4_`、後から埋めた訳 → `gap_`。
   未使用確認:
   ```bash
   grep -c "my_new_key" journey.html
   ```
   期待出力: `0`。if 1以上 → then 別のキー名にする
2. `ja: {` ブロックに追加する。ブロック位置の確認:
   ```bash
   grep -n "^  ja: {" journey.html
   ```
   出た行の下（ブロック内の最終キーの後ろ）に1行追加: `    my_new_key: "新しい文言",`
3. 残り9言語のブロックにも**同じキー・同じ位置（各ブロック末尾）**で訳を追加する。
   ブロック開始行の一覧:
   ```bash
   grep -n -E "^  (en|es|pt|fr|de|it|ko|zh|ar): \{" journey.html
   ```
   訳文のトーンは各言語の既存訳に合わせる。if ja の値に `{v0}` 等がある → then 全言語に同じプレースホルダを全部入れる（訳語の語順に合わせて位置は変えてよい、集合が同じなら通る）
4. 使う側を書く。
   - if HTML の静的テキスト → then `<span data-i18n="my_new_key">新しい文言</span>`
     （タグ内には ja と同じ文を書く = フォールバック）
   - if JS からの動的テキスト → then `TT('my_new_key')`。
     if プレースホルダあり → then `TT('my_new_key', {v0: 値})`
5. チェック実行:
   ```bash
   node tools/i18n_check.js
   ```
   期待出力: 4項目 PASS ＋ `総合判定: GREEN … exit 0`
   - if `FAIL: <言語> に欠落キー … my_new_key` → then その言語への追加漏れ。手順3に戻る
   - if `FAIL: <言語>: my_new_key に欠落プレースホルダ` → then その言語の訳に ja と同じ `{v0}` 等を足して再実行
6. 表示確認: デプロイ後に `?lang=en` `?lang=ar` を付けた URL で新文言の箇所を開く。
   if `my_new_key` という文字列がそのまま見えた → then キー名の typo（呼び出し側と TJ で綴りが違う）。grep で両方の綴りを見比べる

## 3. 手順B: UIテキストを「変更する時」

1. キー名を特定する。if 画面の日本語文言しか分からない → then その文言で grep:
   ```bash
   grep -n "変えたい文言" journey.html
   ```
   ヒットした `ja:` ブロック内の行からキー名を読む
2. ja の値を書き換える
3. if 意味が変わる変更（文言の内容が変わった）→ then 残り9言語の訳も全部書き換える。
   if ja だけの表記修正（句読点・敬体変更など意味は同じ）→ then 他言語はそのままでよい
4. if プレースホルダを増やした・減らした・改名した → then
   1. 10言語すべてで同じ集合に揃える
   2. 呼び出し側の vars も揃える。呼び出し箇所の列挙:
      ```bash
      grep -n "TT('キー名'" journey.html
      ```
5. if そのキーが data-i18n でも使われている → then HTML タグ内のフォールバック文も ja の新しい値に合わせる。使用箇所の確認:
   ```bash
   grep -n 'data-i18n="キー名"' journey.html
   ```
6. チェック実行:
   ```bash
   node tools/i18n_check.js
   ```
   期待出力: `総合判定: GREEN … exit 0`
   - if `FAIL: … プレースホルダ` → then 手順4-1 の揃え漏れ。該当言語を直して再実行
   - if `WARN: <言語>: <キー> に {v0} が複数回` → then 同じプレースホルダを1つの訳に2回書いている。§1.2 のとおり2個目は置換されないので、別名（{v1} 等）に分けて呼び出し側でも渡す

## 4. 手順C: UIテキストを「削除する時」

1. 参照が残っていないことを先に確認する:
   ```bash
   grep -n "キー名" journey.html
   ```
   期待出力: TJ の10言語ブロック内の10行**だけ**。
   - if `TT('キー名'` の行がある → then 先にその呼び出しを削除する（残すと画面にキー名がそのまま出る、§1.2）
   - if `data-i18n="キー名"` の行がある → then 先にその属性（またはタグごと）を削除する
2. TJ の10言語すべてから該当キーの行を削除する
3. チェック実行:
   ```bash
   node tools/i18n_check.js
   ```
   期待出力: `総合判定: GREEN … exit 0`（ja のキー数が1減って表示される）
   - if `FAIL: <言語> に余剰キー … キー名` → then その言語だけ消し忘れ。削除して再実行

## 5. デプロイ前チェックリスト

上から順に実行する。前の項目が通るまで次に進まない。

1. **整合チェック**:
   ```bash
   node tools/i18n_check.js
   echo "exit=$?"
   ```
   期待出力: `総合判定: GREEN ── FAIL 0 件 / WARN 84 件 → exit 0` と `exit=0`
   - if exit 1 → then FAIL 行の言語・キー名を読んで §6 の対処表で直し、再実行
   - if WARN が 84 より多い → then §1.6 の基準値ルールで増分を確認する
2. **本番確認**（デプロイ完了後）:
   ```bash
   node tools/verify_prod.js
   ```
   本番 URL（noahsark-wc2026.pages.dev）に対する自動確認スクリプト。
   使い方・期待出力・失敗時の対処はスクリプト冒頭のヘッダコメントに従う

## 6. 困った時（if-then 対処表)

| 症状 | 原因 | 対処 |
|------|------|------|
| チェッカーが `FAIL: <言語> に欠落キー` | その言語ブロックへの追加漏れ | §2 手順3。訳を追加して再実行 |
| チェッカーが `FAIL: <言語> に余剰キー` | ja に無いキーが残存（typo か消し忘れ） | ja 側が正なら ja に追加、不要なら §4 手順2 で削除 |
| チェッカーが `FAIL: … 欠落/過剰プレースホルダ` | 訳文の `{v0}` 等が ja と不一致 | ja と同じ集合に揃える（§3 手順4） |
| チェッカーが `FAIL: … が空文字` | 訳の入れ忘れ（"" のまま） | 訳文を入れる |
| チェッカーが `FAIL: CN.<コード> に言語欠落` | CN の国名訳が欠けた | 既存行の書式（`CODE: {ja:'…',en:'…',…}`）で追加 |
| チェッカーが `ERROR: 辞書の抽出に失敗` | `const TJ = {` 等の宣言の綴り変更、または波括弧の対応が壊れる編集をした | `grep -n "const TJ" journey.html` で現状確認。直近の編集を見直す |
| 画面にキー名（`js1_…` 等）がそのまま出る | キーの typo または削除済みキーの参照残り | `grep -n "そのキー名" journey.html` で TJ 側と呼び出し側の綴りを見比べる |
| 画面に `{v0}` がそのまま出る | 呼び出し側が vars を渡していない／訳文に同じプレースホルダが2回ある | `grep -n "TT('キー名'" journey.html` で vars を確認。重複なら別名に分ける（§1.2） |
| 言語を切り替えても一部が旧言語のまま | その文字列が TT を通らず const に直書き | チェッカー [5/5] の WARN にその行が出ているはず。§2 の手順で TT 化 |
| ar（アラビア語）でレイアウトが崩れる | rtl 方向は `applyLanguageJ` が `dir="rtl"` を設定して発生する仕様 | 崩れた要素の CSS を `dir` 対応にする（`[dir="rtl"]` セレクタで上書き） |
